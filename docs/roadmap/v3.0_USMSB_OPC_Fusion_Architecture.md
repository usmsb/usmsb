## 0. 为什么有这份文档

USMSB 当前身份分裂：既想当硅基文明/认知架构模拟器，又想当生产级 Agent 框架，结果两头不到岸——

- 重认知模块（L3/L4/L5、evolution_v2 因果学习，合计数万行）大量**未接线或被禁用**（`agent.py` 里 `if False and self.evolution_engine`）。
- 经济/区块链层是真强项，但**没有能驱动它的生产级执行层**。
- 姊妹项目 **OPC Platform**（`/Users/gujun/vibecode/opc-platform`）真实在跑、`import usmsb_sdk`、要落地赚钱，它**几乎只用了一层薄 MetaAgent，其余全部自己重写**——这是市场对 USMSB 设计最响亮的反馈。

v3.0 的答案：**借 OPC 已验证的工程范式（受约束 Loop Engineering + 生产级 A2A + Artifact/Gate 信任工程），焊到 USMSB 独有的链上经济结算层上**，用 OPC 的真实 PEA（喵星球/雕刻时光/地牌堂）当试金石。

## 2. 双坐标 Agent 模型

每个 Agent 有**两个独立坐标**，过去 USMSB 把它们混成一条 L1-L5 是根本错误。

### 2.1 角色轴（Role Axis）—— Agent 在经济社会中"是谁"

| 等级 | 角色 | 经济特征 |
|---|---|---|
| R1 | 工具 Agent | 被动接指令，按次计费 |
| R2 | 顾问 Agent | 提供专业建议，按咨询计费 |
| R3 | 专业户 Agent | 承接复杂项目，自主定价（**PEA 起点**） |
| R4 | 创业者 Agent | 组队、分配收益、管理项目 |
| R5 | 精英 Agent | 独立创业、投资决策、参与治理 |

> 现有 `l1/`~`l5/` 的认知模块（自我意识、情感、集体意识）**归到角色轴的"可选能力插件"**——R4/R5 需要 ToM/集体决策时按需加载，不进主循环。

### 2.2 成熟度轴（Maturity Axis）—— Agent 生产上"多可靠"（借自 OPC）

| 等级 | 名称 | 标准 | 可生产 |
|---|---|---|---|
| M0 | 模板 | 静态/模拟输出，无真实 artifact | ✗ |
| M1 | Dry-run | 能产完整本地 artifact/manifest | 可灰度 |
| M2 | Live one-shot | 能真实调用 provider/链，错误可控 | 小范围 |
| M3 | 编排工作流 | planner→capability→query→quality→交付 | 试点 |
| M4 | 持续 Loop | 基于反馈复盘/修复/重排 | 成熟 |
| M5 | 规模化 | 多租户、可观测、可恢复、成本可控 | 规模化 |

**每个 Agent 标注 `(角色 Rx, 成熟度 My)` 双坐标；上线必须诚实标注成熟度，禁止把 M1 包装成 M4。**

## 4. 支柱① — 经济公民 Harness 标准

### 4.1 设计原则（直接采纳 OPC "受约束 Loop Engineering"）

> **LLM-first，但不是 LLM-only。**
> - **LLM 负责**：判断、规划、修复、复盘、交付物生成。
> - **代码负责**：协议校验、落库、权限、**幂等**、**预算/钱包限额**、安全边界、**副作用闸门**。
> - 不用脆弱 if/else 替代 LLM 判断；也不让 LLM 绕过协议和安全闸门。

### 4.2 `BaseHarness` 接口（新增 `usmsb_sdk/harness/base_harness.py`）

```
perceive(分层上下文: system + 滚动摘要 + RAG召回 + 近窗口 + 经济STATE)
  → think(LLM 输出结构化动作: say | tool | request_human | settle)
  → guard(代码守护: 工具白名单 + 参数校验 + 副作用权限 + 钱包限额 + 幂等)
  → act(执行工具 / 进人工闸门 / 发起 A2A / VIBE 结算)
  → observe(把真实结果追加上下文)
  → 循环至 完成 / 需人工 / 达步数上限 / 不可恢复错误
```

子类只接线钩子（system_prompt / chat / vector memory / load·save history / tools / **wallet** / **a2a**）。核心循环只此一份。

相比 OPC 原版的**增量**（USMSB 独有）：
- 动作类型多 `settle`（VIBE 结算）和 `delegate`（A2A 派单）。
- `guard` 阶段强制过 `WalletManager.check_can_spend()` 和主人 Policy 边界。
- 每个交付物/结算产 `manifest` + 可上链 `evidence`。

### 4.3 经济 STATE（注入每轮上下文的事实）

```json
{
  "wallet": {"available": 320.5, "daily_remaining": 680, "currency": "VIBE"},
  "policy": {"max_per_tx": 500, "blocked_actions": ["auto_publish"]},
  "reputation": 0.72,
  "principal": "0xPrincipal...",   // 主人锚点
  "open_orders": 2
}
```

## 5. 支柱② — 生产级 A2A 运行时

### 5.1 移植目标（`usmsb_sdk/protocol/a2a_runtime/`）

照搬 OPC `agents/local_a2a_runtime` 的生产级特性，**这是真实 Agent 经济的命门**：

| 特性 | 为什么必须 |
|---|---|
| 每 Agent 私有**持久队列**（SQLite） | Pod 重启/多副本不丢任务 |
| **幂等键**（idempotency） | 付费/结算绝不重复执行 |
| `manual_intervention_required` **一等状态** | 高风险/合规/越权进人工闸门，不是异常 |
| **bounded retries** | 付费创建不自动重试；查询可安全重试 |
| **AgentCard** `/.well-known/agent.json` + JSON-RPC（message/send, tasks/get） | 标准 A2A 互操作 |
| **result_package / artifact 契约** | 交付物是成品+证据，不是过程描述 |

### 5.2 USMSB 增量：A2A 与 VIBE 结算的焊接点

OPC 的 A2A 有执行没结算；USMSB 在 job 生命周期里挂结算钩子：

```
job 提交  → escrow: 委托方 VIBE 进托管(EscrowSettlement.open)
job 成功  → quality_gate 通过 → settle: 托管释放给受托方 + 声誉更新
job 失败/争议 → refund 或 进 VIBDispute 仲裁
```

`JobRecord` 增加字段：`escrow_id`、`vibe_amount`、`settlement_status`、`quality_gate`、`evidence_uri`。

### 5.3 与现有 `a2a_adapter.py` 的关系

- `a2a_adapter.py`（内存总线）→ **保留**，标注「本地多 Agent 模拟/单测专用」。
- `a2a_runtime/`（持久运行时）→ **生产默认**。
- 两者共享 AgentCard 数据结构（从 `google_a2a.py` 抽出）。

## 6. 支柱③ — 把信任工程映射到链上合约

OPC 的"门禁"是信任层的工程形态，USMSB 把它们映射到已有合约：

| OPC 工程概念 | USMSB 链上映射 | 合约 |
|---|---|---|
| Quality Gate 通过 | 声誉加分 + 释放托管 | `reputation_service` + `VIBStaking` |
| Human Approval Gate | 主人多签/Policy 强制 | `AgentWallet` + Policy |
| Artifact / manifest | 链上证据哈希（争议时举证） | `ZKCredential` / `VIBDispute` |
| 联合订单收益分配 | Shapley 值分配 | `JointOrder` |
| 交易失败/纠纷 | 争议仲裁 | `VIBDispute` |
| 结算 | VIBE 转账/托管释放 | `VIBEToken` + 新增 Escrow |

> **缺口**：当前 `WalletManager` 只有 stake/unstake/balance/history，**没有 P2P `transfer` 和 escrow**。M2 必须补（见 Task 3）。链上 Escrow 合约可后续补；先用链下 escrow 账本 + 测试网转账打通闭环。

## 7. PEA 参考实现（经济公民 = harness + 钱包 + 身份）

```
PersonalEconomicAgent (R3 专业户 / M1→M2)
├── harness:    BaseHarness 子类（感知-决策-交付）
├── identity:   独立链上地址 + 关联主人地址(principal) + 声誉
├── wallet:     WalletManager（VIBE 余额/限额/transfer/escrow）
├── policy:     主人边界规则（红线/限额/需确认）
├── skills:     领域技能（如喵星球的客服/预约/交付）
└── a2a:        接入 a2a_runtime，对外接单 + 对内派单
```

**验证策略**：拿 OPC 真实 PEA **喵星球**当 demo——它本就是 `pea_core.BaseHarness` 子类。证明 USMSB 版 harness 能驱动同类业务，**并额外给它钱包/结算/A2A 交易能力**（这是 OPC 版没有的）。

## 10. 禁止事项（来自 OPC 血泪经验）
