## 二、各模块关系分析

### 2.1 现有架构重叠问题

```
问题：多个模块有相似职责
```

| 职责 | 涉及的模块 |
|------|-----------|
| **Agent 执行循环** | `l2/agent.py`, `platform/external/meta_agent/MetaAgent`, `harness/ExecutionEngine` |
| **LLM 调用** | `l2/agent.py._call_llm`, `meta_agent/LLMManager`, `harness/ExecutionEngine` |
| **工具注册** | `l2/tools.py`, `meta_agent/tools/registry.py`, `harness/ExecutionEngine` |
| **目标管理** | `l3/`, `meta_agent/GoalEngine`, `harness/ExecutionOrchestrator` |
| **记忆管理** | `l2/memory.py`, `meta_agent/MemoryManager`, `l5/CollectiveMemory` |
| **多 Agent 协作** | `l5/`, `harness/ExecutionOrchestrator` |

### 2.2 MetaAgent 与 L2-L5 的关系

```
MetaAgent (platform/external/meta_agent/)
    │
    ├── 感知 ──────────→ L1 RuleEngine (简化)
    │
    ├── 工具执行 ──────→ L2 tools.py (复用)
    │
    ├── 目标/学习 ─────→ L3 PurposeGenerator + IntrinsicMotivation
    │
    ├── 自我意识 ──────→ L4 SelfModel + Metacognition
    │
    ├── 集体智能 ──────→ L5 CollectiveIntelligence
    │
    └── 工程化 ────────→ harness/ (Execution, Knowledge, Policy, Governance)
```

**结论**: MetaAgent 是一个**横向整合**模块，它应该**调用** L2-L5 的能力，而不是重新实现。

### 2.3 MetaAgent 与 harness 的关系

```
MetaAgent
    │
    ├── ExecutionService ──────────→ harness/ExecutionEngine
    │
    ├── KnowledgeBase ─────────────→ harness/KnowledgeLayer
    │
    ├── PolicyRuntime ─────────────→ harness/PolicyRuntime
    │
    └── GovernanceLayer ───────────→ harness/GovernanceLayer
```

**结论**: MetaAgent 使用 harness 作为执行基础设施。

### 2.4 OpenHarness 集成位置

```
OpenHarness (外部库)
    │
    ├── QueryEngine ──────→ 可以替换 MetaAgent 的 LLMManager
    │
    ├── ToolAdapter ──────→ 可以替换 MetaAgent 的 ToolRegistry
    │
    ├── MemoryAdapter ────→ 可以替换 MetaAgent 的 MemoryManager
    │
    ├── SwarmAdapter ──────→ 可以实现 L5 集体智能
    │
    └── HookAdapter ──────→ Self-Observation (L4)
```

## 三、架构重构方案

### 方案 A: MetaAgent 为中心（推荐）

```
                    ┌─────────────────────────────────────┐
                    │          MetaAgent (中心)           │
                    │  platform/external/meta_agent/      │
                    └─────────────────────────────────────┘
                                      │
           ┌──────────────────────────┼──────────────────────────┐
           │                          │                          │
           ▼                          ▼                          ▼
    ┌──────────────┐         ┌──────────────┐         ┌──────────────┐
    │  L2 (工具性) │         │  L3 (目标性)  │         │  L4 (自我)   │
    │  L2Agent     │         │ PurposeGen   │         │ SelfModel    │
    └──────────────┘         └──────────────┘         └──────────────┘
           │                          │                          │
           └──────────────────────────┼──────────────────────────┘
                                      ▼
                           ┌──────────────────────┐
                           │  harness/ (执行层)    │
                           │  ExecutionEngine      │
                           │  KnowledgeLayer       │
                           │  PolicyRuntime       │
                           └──────────────────────┘
                                      │
                                      ▼
                    ┌─────────────────────────────────────┐
                    │     OpenHarness (可选增强)           │
                    │  QueryAdapter → LLM 调用              │
                    │  ToolAdapter → 工具执行               │
                    │  SwarmAdapter → 多 Agent 协作        │
                    └─────────────────────────────────────┘
```

**优点**:
- MetaAgent 是完整的 Agent，保持其完整性
- L2-L5 作为组件被 MetaAgent 调用
- harness 作为执行基础设施
- OH 作为可选增强层

**需要改动**:
1. MetaAgent 应该**委托**给 L2-L5，而不是自己实现
2. L2-L5 需要重构为可组合的组件
3. OH 适配层作为 MetaAgent 的**可选**注入

### 方案 B: 统一 Agent 基类

```
                 ┌─────────────────────────────────────┐
                 │     BaseAgent (抽象基类)              │
                 │  - LLM 调用                          │
                 │  - 工具执行                          │
                 │  - 记忆管理                          │
                 └─────────────────────────────────────┘
                         │
         ┌───────────────┼───────────────┐
         │               │               │
         ▼               ▼               ▼
    ┌─────────┐    ┌─────────┐    ┌─────────┐
    │ MetaAgent│    │ L2Agent │    │ L4Agent │
    │ (完整)  │    │ (工具)  │    │ (自我)  │
    └─────────┘    └─────────┘    └─────────┘
         │
         ▼
    ┌─────────────────────────────────────┐
    │     OpenHarness (底层基础设施)       │
    │  QueryEngine → BaseAgent.LLM        │
    │  ToolAdapter → BaseAgent.Tools       │
    └─────────────────────────────────────┘
```

**优点**:
- 统一架构
- OH 作为所有 Agent 的底层

**需要改动**:
- 大量重构现有代码

## 四、OpenHarness 集成的正确位置

### 4.1 不应该做的事

❌ 不应该在 L2、L3、L4、L5 各自独立集成 OH
❌ 不应该新建一堆 `OHL2Agent`、`OHL3Orchestrator` 等类
❌ 不应该把 MetaAgent 的功能拆分到各层

### 4.2 应该做的事

✅ **MetaAgent 是入口**，OH 注入到 MetaAgent
✅ **L2-L5 作为组件**，被 MetaAgent 调用
✅ **harness 作为执行层**，被 MetaAgent 调用
✅ **OH 作为可选增强**，通过依赖注入

### 4.3 具体集成方式

```python
# 方式 1: 依赖注入 (推荐)
class MetaAgent:
    def __init__(self, config, llm_adapter=None, tool_adapter=None):
        self.llm = llm_adapter or DefaultLLMManager()
        self.tools = tool_adapter or DefaultToolRegistry()
        
        # L2-L5 作为内部组件
        self.l2 = L2Agent(self.llm, self.tools)
        self.l3 = PurposeGenerator(self.l2)
        self.l4 = SelfModel(self.l3)
        self.l5 = CollectiveIntelligence(self.l4)

# 方式 2: OH 作为 llm_adapter
from usmsb_sdk.adapters.openharness import OpenHarnessIntegration

oh_integration = OpenHarnessIntegration()
await oh_integration.initialize()

meta_agent = MetaAgent(
    config=config,
    llm_adapter=oh_integration.query_adapter,  # OH QueryEngine
    tool_adapter=oh_integration.tool_adapter,  # OH ToolAdapter
)
```

## 五、建议讨论点

1. **MetaAgent 是否应该成为唯一入口？**
   - 还是 L2-L5 可以独立使用？

2. **L2-L5 的关系是什么？**
   - 串行依赖（ L1→L2→L3→L4→L5）？
   - 还是可组合的组件？

3. **harness 的定位是什么？**
   - 执行引擎？
   - 还是完整的 MAS 基础设施？

4. **OH 集成的深度？**
   - 完全替换 LLM/Tool？
   - 还是仅作为可选增强？
