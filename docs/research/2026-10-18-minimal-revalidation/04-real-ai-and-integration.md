# 真实 AI 行为与跨产品接入

日期：2026-10-18。所有环境均本机隔离；工具资料与历史学习为明确标注的合成数据，根推理为实际 Codex CLI。人工查阅模型原始结果及子工具原件，不以 `succeeded` 代替语义验收。

## 1. 决策归属与实际链路

真实外部主体通过现有 Morrow `CoordinatorCodexExecutor`、MCP 能力目录/委派/读取接口，自己选择是否读取、读什么、停止还是修订。未给固定调用序列、正确答案或要求使用全部额度。每轮获准3次本地只读取证；没有开放 shell、浏览器、付款、发布、联系人或生产数据。

Wishbud/Morrow：既有 pursuit → 冻结输入与所选历史 learning → 默认 Agent prompt 中的经验依据视图 → 外部 Codex → 获准子能力 → 原件及回执 → 带依据的候选/下一步 → 持久化新 learning 及其目标/引用版本。

OPC 伙伴案例：同一委派入口 → 本地 `LocalA2ARuntime` → synthetic handler → 完整 A2A task（业务原件与 `metadata.execution_evidence`）→ Morrow artifact → 外部 AI。

这是真实本地产品路径与真实模型调用，但 provider 的业务资料是合成的。测试桥接器保留完整 task；不能据此说所有生产消费方都已转发 metadata。绕开 LocalA2ARuntime 的 OPC 路径不在此次覆盖内。

USMSB 计算器是可选工具，此次自然语言 AI 演练没有调用它，不能把数学错误界套到模型的文字判断上。模拟实验与真实 AI 实验是两类独立证据。

这些结果支持“在此上下文与授权工具下能按新证据调整行动/建议”，不支持长期自治、独立多方协作或跨场景成功率。模型存在明示任务提示，案例非盲测随机样本；未运行同模型无新上下文视图的配对消融，**不能归因新增视图优于原版本**，更不能说其他模型/产品做不到。

旧经验由脚本明确构造，没有前一轮模型真实形成经验→真实目标修订→后续迁移的纵向链。工具目录名称有语义信息，missing读取的材料本身给出测量方向；模型组合形成具体草案，不等于无提示原创发明。2次少于3次上限，也不证明达到最小充分取证成本。partner比另两案多一层OPC包装，不是完全同配置比较。

## 3. 从失败到修复

第一处通用缺口：MCP已把子轮 ID 和回执交给主体，客户端和服务端完成校验却只补入子 artifact。有效引用被标 `outside_input`。新 `child_execution_reference` 只投影当前已授权、成功且非晚到子轮的已有字段；两端各自执行原权属/状态检查。它不跨空间取数据、不使子回执成为可信业务结论、不改冻结父输入。

第二处通用缺口：原提示只说“unknown停止”，未区分 `status=unknown` 与 `cost_status=unknown`。改成执行未知仍停止；已成功返回但未报价只能记货币成本未知，不能记零、扩权或重复创建。是否继续仍由主体在原调用额度内判断，原预算执行逻辑未放宽。

修复后增加客户端和服务端引用回归，并重新运行 goal。失败的原 action、报告和工具读取保持原样；goal-v2不是改写旧运行或补交伪造回执。

回执计量不等于账单；缓存/套餐折算与货币费用未知，不能按公开单价臆算成实际支付。子读取是本地合成handler，回执明确无子LLM推理；整体真实模型成本仍不为零。所有临时loopback服务器和子worker正常结束；没有后台生产服务留存。

Wishbud仓库复现入口（会新调用模型，需要当前操作者授权与本机已登录CLI；不能作为无费用单元测试）：

```powershell
python scripts/morrow_revalidation_probe.py --case goal --directory <新的绝对输出目录> --execute
python scripts/morrow_revalidation_probe.py --case missing --directory <新的绝对输出目录> --execute
python scripts/morrow_revalidation_probe.py --case partner --directory <新的绝对输出目录> --opc-runtime --execute
```

去掉 `--execute` 仅预检，零模型调用。已有输出目录拒绝复用。脚本每case仅发一次根调用，不自动重试unknown/失败。实际模型按既有CLI宿主配置选择；这份回执未提供可核验的具体模型修订ID，不猜测型号，也不导出本机账户配置。

发布的 [results](real_ai/results/) 是严格白名单导出的模型原始 action、所选合成历史、工具原件、保存的turn、计量和源文件SHA。不是完整私有数据库；不含临时token、lease、认证材料或本机路径。生成器[export_evidence.py](real_ai/export_evidence.py)只读已完成运行，不调用模型；`--check` 与本机原件逐字比对。SHA用于定位版本，不是独立第三方证明。

首批四次运行没有在启动时冻结所有dirty源码和完整组装prompt，这限制了严格复现。审查后脚本增加`audit_version=2`：执行前保存选定源码原字节/摘要，调用runner前保存实际组装prompt；不保存环境变量/凭据，亦不假称包含模型供应商内部指令或完整依赖镜像。该补充仅通过无模型测试验证，没有为补清单重跑付费调用，不能倒填成首批运行当时已有的证据。历史原件仍保持不变。

## 5. 与生态愿景的关系

扩大了主体可以理解和核对的空间：历史不再脱离原目标与来源；伙伴成功回执不自动成为业务成功；缺失真实结果可以促使主体设计取证方法而非伪造增长。

没有新增销售、翻译或财务专用业务流程。案例中的转换规则、测量方案与下一步全部是模型产物，不是平台预写答案。但这三个有限演练只覆盖开放协作的一小段，不代表需求形成、创新、长期执行、价值分配、独立主体博弈与群体演化均已验证。
