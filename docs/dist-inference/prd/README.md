## 1. 产品概述

### 1.1 产品定位

USMSB 分布式推理平台是 USMSB 网络中的一个**超级智能体**，旨在将 USMSB 网络中分布式的 GPU 计算资源整合成一个统一的 LLM 推理服务平台。

**核心定位**：
- 不改变 USMSB SDK 的定位（去中心化 Agent 网络）
- 作为 USMSB 网络中独立存在的超级智能体
- 与 USMSB SDK Agent 通过标准协议 (A2A/MCP) 通信，不耦合

### 1.2 目标用户

| 用户类型 | 使用方式 | 典型场景 |
|---------|---------|---------|
| **C 端用户** | API / Agent 对话 | 调用 LLM 推理服务生成内容 |
| **内部 Agent** | 通过 A2A/MCP 调用 | USMSB SDK 中的 Agent 使用 LLM 能力 |

### 1.3 商业模式

```
┌─────────────────────────────────────────────────────────────────┐
│                        商业模式                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   GPU 持有者 ──(提供 GPU 算力)──▶ 平台 ──(提供 LLM 服务)──▶ 用户  │
│        │                                   │                      │
│        │   按 GPU 卡时收费 (Vibe)          │   按 Token 收费      │
│        │   (平台抽 30%)                    │   (平台抽 30%)        │
│        ◀───────────────────────────────────                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

**计费模式**：
- **GPU 卡时**：底层资源计费，按 GPU 实际使用时长
- **Token**：上层服务计费，按输入+输出的 Token 数
- **结算货币**：统一使用 Vibe 代币
- **平台抽成**：30%

**欠费处理**：
- 先完成本次任务，记录欠费金额
- 下次使用时必须先还清欠费才能继续使用

## 2. 功能需求

### 2.1 核心功能列表

| 优先级 | 功能 | 描述 |
|-------|------|------|
| P0 | 全局调度 Agent | 接收请求、路由到合适节点、执行推理、返回结果 |
| P0 | 节点执行 Agent | 在 GPU 节点上执行 LLM 推理 |
| P0 | GPU 资源管理 | 发现、注册、监控 GPU 资源 |
| P0 | OpenAI 兼容 API | 提供 `/v1/chat/completions` 等标准接口 |
| P1 | Vibe 计费系统 | GPU 卡时 + Token 计费，欠费管理 |
| P1 | 模型管理 | 预置模型 + 用户自安装，模型预加载 + 按需加载 |
| P1 | 节点故障处理 | 节点故障时自动换节点重试 |
| P2 | 多卡并行推理 | Tensor Parallelism 支持 |
| P2 | 流式输出 | WebSocket 流式响应 |
| P3 | 用户自安装模型 | 用户上传自定义模型 |

### 2.2 模型管理

**预置模型**：
- 平台预先安装的模型
- 来源：HuggingFace Hub / ModelScope

**用户自安装模型**：
- 用户可以上传自己的模型
- 存储：S3/OSS + 本地缓存

**加载策略**：
- 常用模型：启动时预加载，持续占用显存
- 其他模型：按需加载，有冷启动延迟

### 2.3 节点管理

**粒度**：按**节点**管理，而非按卡管理
- 卡多的节点：做需要多卡的场景
- 卡少的节点：做需要卡少的场景

**资源发现**：
- Node Executor 启动时主动向 Global Scheduler 注册
- Global Scheduler 定期主动扫描网络

**单节点最低配置**：
- GPU 显存：最低 24GB
- GPU 类型：支持 CUDA 的 GPU

## 3. 非功能需求

### 3.1 性能需求

| 指标 | 目标 |
|------|------|
| API 响应时间 | < 2s (不含推理时间) |
| 推理吞吐量 | 取决于 vLLM 性能 |
| 支持并发请求数 | 支持多节点水平扩展 |

### 3.2 可用性

- 节点故障时自动重试
- 单节点故障不影响整体服务

### 3.3 扩展性

- 支持水平扩展：增加更多 GPU 节点
- 支持垂直扩展：单节点增加更多/更大 GPU

### 3.4 安全性

- API 认证（Phase 2）
- 节点身份验证（Phase 2）

## 5. Phase 计划

### Phase 1: MVP (当前阶段)
**目标**：独立进程快速验证核心流程

- [ ] Global Scheduler 核心 (API Server + Router)
- [ ] 单节点 vLLM 集成 (单机单卡)
- [ ] 最简调度 (按节点负载选)
- [ ] 基础计费 (GPU 卡时)
- [ ] OpenAI 兼容 API

### Phase 2: 分布式能力
- [ ] Node Executor 注册/心跳机制
- [ ] GPU 资源池管理
- [ ] 模型预加载 + 按需加载
- [ ] 节点故障重试
- [ ] Token 计费

### Phase 3: 生态完善
- [ ] 多卡 TP 支持
- [ ] 用户自安装模型
- [ ] Vibe SDK 集成
- [ ] WebSocket 流式输出

## 6. 风险与挑战

| 风险 | 影响 | 缓解措施 |
|------|------|---------|
| GPU 资源分散 | 调度复杂度高 | 按节点管理，匹配场景 |
| 模型显存需求大 | 单卡无法运行大模型 | 支持多卡 TP |
| 视频生成模型过大 | 加载慢、显存占用高 | 按需加载，预留足够显存 |
| USMSB SDK 耦合 | 破坏现有架构 | 独立超级智能体，不修改 SDK |

## 8. 术语表

| 术语 | 定义 |
|------|------|
| Global Scheduler | 全局调度 Agent，负责接收请求、路由、计费 |
| Node Executor | 节点执行 Agent，负责在 GPU 节点上执行推理 |
| GPU Pool | GPU 资源池，管理所有可用 GPU 节点 |
| Vibe | USMSB 网络中的结算代币 |
| TP (Tensor Parallelism) | 张量并行，多卡并行推理技术 |
| vLLM | 高性能 LLM 推理引擎 |
