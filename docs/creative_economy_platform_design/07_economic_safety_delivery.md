# IAP / Athena 经济安全边界修复

本次针对已有实现中的成功误报；不声明生产资金或 ZK 网络已落地。

- `LLMQualityGate` 缺失评审器、模型错误、非法结论返回 `unknown`，空交付返回 `failed`。无评审器的 PEA handler 与缺失 quality_gate 的 A2A handler 不再默认通过。
- 联合订单缺少供应商直接拒绝；缺失/未知评审保持托管待复核。退款或分账只有后端确认成功才报告成功，返回 escrow_id 供对账。
- `VibeSettlementBackend` 使用 SQLite 预写日志，转账前冻结预留和计划，逐笔保存确认/未知状态。相同 escrow_id 不重新扣款，并发 release/refund 只有一个可以进入转账阶段。
- 部分分账失败、超时、取消、进程中断后的在途状态禁止自动重试与整单退款。日志可读用于核对，但未提供没有供应商证据的“强制成功”接口。
- 钱包适配器必须指定持久日志路径；内存日志仅用于测试。浮点 legacy VIBE 接口不是法币支付轨道，还需要整数单位、最终回执、供应商幂等和对账恢复。
- SDK 原 ZK 方法生成固定曲线点、验证时只看时间和状态。现已停止生成与发放，并对校验返回 False；旧占位凭据不授予权限。真正电路与验证后端未实现，不以哈希或身份签名冒充 ZK。

已有链上合约、资产拆分和服务计算模块的存在不构成生产审计、法律权利、市场流动性或已实现价值证明。
`PeaMarket` 的内存账本和缺失贡献评估器时的均分仍属于实验演示，不是客户已签署的真实收益分配协议。

安全回归：`tests/unit/test_economic_fail_closed.py`；兼容回归包含 PEA 市场、联合订单、团队、转包、托管、A2A 运行时与创意服务测试。
本机全量单测另外报告缺少链上 artifacts、未安装 OpenHarness extra，以及 Windows 路径/权限断言失败；这些不应被归纳为全库通过。
