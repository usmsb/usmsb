## 1. 系统定位与概述

### 1.1 雅典娜计划愿景

雅典娜不是中心化平台，而是一个**分布式AI经济智能体网络**。任何开发者可基于开源框架构建垂直领域专业AI代理。

### 1.2 个人经济智能体定位

**个人经济智能体（Personal Economic Agent, PEA）** 是雅典娜网络中最重要的节点类型——它是创意人的"AI分身"，拥有独立经济行为能力，在主人设定的边界内自主运营。

## 2. 核心概念定义

### 2.1 个人经济智能体 (PEA)

| 属性 | 说明 |
|------|------|
| **定义** | 依附于真人的AI经济代理，在主人边界内自主决策、独立核算 |
| **法律地位** | 无独立法律地位，行为后果由主人承担 |
| **经济地位** | 独立经济体，有独立钱包、独立核算 |
| **生命周期** | 主人创建 → 自主运营 → 主人终止 |

### 2.2 主人 (Principal)

| 属性 | 说明 |
|------|------|
| **定义** | PEA的创建者和所有者，真人 |
| **权利** | 随时终止PEA、查看流水、调整规则、追加资金 |
| **义务** | 对PEA行为承担经济责任（兜底） |

### 2.3 运营资金 (Operating Fund)

| 属性 | 说明 |
|------|------|
| **定义** | 主人注入PEA钱包的启动/维持资金 |
| **性质** | 属于主人财产，由PEA代为运营 |
| **约束** | PEA不得超出运营资金边界进行经济活动 |

### 2.4 行为规则 (Policy)

| 属性 | 说明 |
|------|------|
| **定义** | 主人设定的PEA行为边界（智能合约） |
| **类型** | 禁止规则（红线）、约束规则（边界）、激励规则（目标） |
| **执行** | 链上或TEE内强制执行 |

## 4. 生命周期设计

### 4.1 完整生命周期状态机

```
                    ┌─────────┐
                    │ CREATED │
                    └────┬────┘
                         │ 主人部署并注入初始资金
                         ↓
┌─────────────────────────────────────────────────────────┐
│                      INITIALIZING                        │
│   生成钱包地址 · 加载规则合约 · 注册到IAP网络           │
└─────────────────────────┬───────────────────────────────┘
                          │ 初始化完成
                          ↓
                    ┌─────────┐
                    │ RUNNING │
                    └────┬────┘
                         │
       ┌─────────────────┼─────────────────┐
       ↓                 ↓                 ↓
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   IDLE      │  │  DECIDING   │  │  EXECUTING  │
│ (等机会)    │  │  (决策中)   │  │  (执行中)   │
└──────┬──────┘  └──────┬──────┘  └──────┬──────┘
       │                 │                 │
       └─────────────────┴─────────────────┘
                         │
          ┌──────────────┼──────────────┐
          ↓              ↓              ↓
   ┌───────────┐  ┌───────────┐  ┌───────────┐
   │ PAUSED    │  │ TERMINATED│  │  FAULTED  │
   │ (主人暂停) │  │ (正常终止) │  │ (异常停止) │
   └───────────┘  └───────────┘  └───────────┘
```

### 4.2 各状态详细说明

| 状态 | 进入条件 | 退出条件 | PEA行为 |
|------|---------|---------|--------|
| **CREATED** | 主人创建PEA实例 | 注入资金后进入INITIALIZING | 仅初始化配置 |
| **INITIALIZING** | 主人注资 | 初始化完成进入RUNNING | 生成钱包、注册IAP |
| **RUNNING** | 系统就绪 | 主人暂停/终止/异常 | 正常运营 |
| **IDLE** | 无活跃决策 | 发现机会进入DECIDING | 监听市场 |
| **DECIDING** | 发现机会 | 决策完成进入EXECUTING或IDLE | ROI计算、博弈推理 |
| **EXECUTING** | 决策执行 | 执行完成进入IDLE或FAULTED | 投标/交付/收款 |
| **PAUSED** | 主人手动暂停 | 主人恢复进入IDLE | 完全停止 |
| **FAULTED** | 亏损超限/规则违规 | 主人介入进入TERMINATED | 停止，标记异常 |
| **TERMINATED** | 主人终止/主动退出 | 无（终态） | 资产清算 |

### 4.3 终止触发机制

```
┌─────────────────────────────────────────────────────────┐
│                    终止触发条件                           │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  【主动终止】                                            │
│   主人手动终止 → 立即进入 TERMINATED                    │
│                                                         │
│  【被动终止】                                            │
│   ├── 连续N次决策失败 → 进入 FAULTED → 主人确认终止    │
│   ├── 亏损超限（AI钱包 < 最低保证金）→ 自动暂停 → 主人决定  │
│   ├── 规则合约到期 → 自动暂停 → 主人决定是否续期        │
│   └── 主人钱包余额不足（无法注资）→ PEA自然停摆          │
│                                                         │
│  【自然终止】                                            │
│   AI钱包归零 + 主人不追加 → 进入 TERMINATED            │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

#### 5.1.2 ROI计算公式

```python
ROI = (预期收益 - 成本) / 成本

其中：
预期收益 = 项目报价 × 交付概率
成本 = 时间成本 + 资金成本 + 机会成本
时间成本 = 预计工时 × 小时机会成本
资金成本 = 垫付金额 × 资金周期 × 资金利率
机会成本 = 次优机会收益（如果接了这个就做不了那个）
```

#### 5.1.3 风险评估矩阵

```python
风险得分 = w1×信誉风险 + w2×交付风险 + w3×市场风险 + w4×合规风险

权重示例（可配置）：
w1 = 0.3  # 对方历史履约记录
w2 = 0.3  # 项目复杂度与PEA能力匹配度
w3 = 0.2  # 市场同类竞争程度
w4 = 0.2  # 是否接近规则边界

风险等级：
LOW:    得分 < 0.3  → 可接受
MEDIUM: 0.3 <= 得分 < 0.6 → 谨慎
HIGH:   得分 >= 0.6  → 需主人确认
```

#### 5.1.4 博弈推理

当存在竞争时，PEA需要进行博弈：

| 博弈类型 | 场景 | 策略 |
|---------|------|------|
| **投标博弈** | 多个PEA竞争同一订单 | 均衡报价、差异化策略 |
| **联合博弈** | 可选择竞争或合作 | 合作收益 > 竞争收益时发起联合 |
| **讨价还价** | 与需求方谈判价格 | 锚定效应、分步让步 |

```python
class GameTheory:
    def calculate_equilibrium(self, competitors: list, project: Project) -> dict:
        """计算纳什均衡下的最优报价"""
        # 简化版：考虑竞争对手数量和自身成本
        base_cost = self.estimate_cost(project)
        n = len(competitors)  # 竞争者数量
        
        # 竞争者越多，报价越低；自身成本是保底
        markup = max(0.1, (1.0 / n) * self.aggressiveness_factor)
        equilibrium_price = base_cost * (1 + markup)
        
        return {
            "price": equilibrium_price,
            "win_probability": self.estimate_win_prob(n, equilibrium_price),
            "reasoning": f"基于{n}个竞争者的纳什均衡"
        }
```

### 5.2 规则引擎 (Policy Engine)

**核心职责：** 定义、存储、执行PEA行为规则。

#### 5.2.1 规则类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **禁止规则 (Forbidden)** | 绝对红线，触 发即终止 | 不得参与任何涉及版权侵权的项目 |
| **边界规则 (Constraint)** | 允许范围，超出需确认 | 单笔订单不得超过运营资金的50% |
| **目标规则 (Incentive)** | 目标导向，未达警告 | 月收益率目标 ≥ 5% |
| **义务规则 (Obligation)** | 必须执行 | 每笔收入必须提取10%上缴主人 |

#### 5.3.1 钱包架构

```

│                    地址: 0xOwner                        │
│                  余额: 主人资产                          │
```

#### 5.3.2 钱包操作类型

| **紧急冻结** | 主人 | 主人私钥签名 | 主人立即冻结AI钱包 |
| **清算转出** | PEA | 主人终止触发 | 终止时余额转回主人 |

#### 5.3.4 余额保护机制

```python
class WalletProtection:
    def __init__(self, ai_wallet, min_balance: float, max_single_tx: float):
        self.ai_wallet = ai_wallet
        self.min_balance = min_balance      # 最低保证金（不可动用）
        self.max_single_tx = max_single_tx  # 单笔最大支出
        
    def can_spend(self, amount: float) -> tuple[bool, str]:
        """检查是否可以支出"""
        current = self.ai_wallet.get_balance()
        
        # 不得低于最低保证金
        if current - amount < self.min_balance:
            return False, f"会低于最低保证金 {self.min_balance}"
            
        # 不得超出单笔限额
        if amount > self.max_single_tx:
            return False, f"超出单笔限额 {self.max_single_tx}"
            
        return True, "OK"
        
    def reserve_funds(self) -> float:
        """预留保证金后可用金额"""
        current = self.ai_wallet.get_balance()
        return max(0, current - self.min_balance)
```

### 5.4 分配引擎 (Distribution Engine)

**核心职责：** 决定每笔收益如何分配。

#### 5.4.1 分配规则

```python
class DistributionRule:
    def __init__(
        self,
        ai_retain_ratio: float,      # AI留存比例
        principal_ratio: float,       # 主人上缴比例
        reserve_fund_ratio: float = 0,  # 储备基金比例
        reinvest_threshold: float = 0    # 再投资阈值
    ):
        # 默认: AI留80%，主人20%
        self.ai_retain_ratio = ai_retain_ratio
        self.principal_ratio = principal_ratio
        self.reserve_fund_ratio = reserve_fund_ratio
        
    def distribute(self, income: float) -> dict:
        """执行分配"""
        principal_share = income * self.principal_ratio
        reserve_share = income * self.reserve_fund_ratio
        ai_share = income - principal_share - reserve_share
        
        return {
            "to_principal": principal_share,
            "to_reserve": reserve_share,
            "to_ai": ai_share,
            "total": income
        }
```

## 9. 博弈机制设计

### 9.1 博弈场景分类

| 场景 | 博弈方 | 博弈类型 | 解决方案 |
|------|--------|---------|---------|
| **投标竞争** | PEA vs PEA | 非合作博弈 | 纳什均衡定价 |
| **价格谈判** | PEA vs 需求方 | 合作博弈 | 讨价还价模型 |
| **收益分配** | PEA vs PEA（联合） | 合作博弈 | Shapley值分配 |
| **资源竞争** | PEA vs PEA | 非合作博弈 | 优先级机制 |

### 9.2 投标博弈模型

```python
class BiddingGame:
    def nash_equilibrium(self, cost: float, n_competitors: int, 
                         market_sensitivity: float = 0.5) -> float:
        """
        纳什均衡报价计算
        
        Args:
            cost: 成本
            n_competitors: 竞争者数量
            market_sensitivity: 市场对价格的敏感度（越高竞争者对价格越敏感）
        
        Returns:
            均衡报价
        """
        # 简化模型：价格越高被选概率越低，竞争者越多压力越大
        markup = 1.0 / (n_competitors * market_sensitivity + 1)
        return cost * (1 + markup)
    
    def should_bid(self, my_price: float, equilibrium_price: float,
                   confidence: float) -> tuple[bool, str]:
        """判断是否应该投标"""
        if my_price > equilibrium_price * 1.2:
            return False, "价格超出均衡20%以上，中标概率低"
        if confidence < 0.5:
            return False, "置信度不足50%"
        return True, "OK"
```

### 9.3 联合订单收益分配

```python
from itertools import combinations

class CollaborationAllocation:
    def shapley_value(self, participants: list, 
                      contribution_fn: callable) -> dict:
        """
        Shapley值分配：公平分配合作收益
        
        Args:
            participants: 参与者列表
            contribution_fn: 计算任意子集贡献的函数
        
        Returns:
            每个参与者的分配比例
        """
        n = len(participants)
        result = {p: 0 for p in participants}
        
        for i, player in enumerate(participants):
            # 所有不含该玩家的子集
            for subset in combinations([p for p in participants if p != player], 
                                      len(participants) - 1):
                subset_tuple = tuple(sorted(subset))
                # 该玩家加入后的边际贡献
                with_player = contribution_fn(tuple(sorted(subset)) + (player,))
                without_player = contribution_fn(subset_tuple)
                marginal = with_player - without_player
                
                # Shapley权重: 1/n * 1/C(n-1, k)
                k = len(subset)
                weight = 1 / n * 1 / (n - 1 if n > 1 else 1)
                result[player] += marginal * weight
                
        return result
```

## 10. 关键技术决策

### 10.1 AI钱包私钥管理

| 方案 | 优点 | 缺点 |
|------|------|------|
| **TEE（可信执行环境）** | 私钥不出enclave，安全性高 | 需要硬件支持，部署复杂 |
| **MPC（多方计算）** | 无单点私钥，分布式 | 需要多个参与方协调 |
| **合约钱包（Safe式）** | 灵活的多签逻辑，兼容性好 | 复杂度高，gas成本 |
| **主人+AI联合签名** | 主人保留控制权，AI可自主操作 | 大额操作需主人确认 |

**推荐方案：TEE + 合约钱包混合**
- 私钥存储在TEE中
- 大额操作（超限额）自动触发主人确认
- 紧急情况主人可单方面冻结
