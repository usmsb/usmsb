# USMSB 开放协作内核：整改设计与验收规范

状态：实施设计；交付证据见同目录 `open-collaboration-delivery.md`。
日期：2026-09-29。基线：`origin/main@2a0208f`。本设计优先于历史路线图中的产品定位；不把历史实验删除或宣称为已完成。

## 1. 定位与非目标

USMSB 是独立于某个 World、运营方、模型、执行框架和支付资产的开放协作基础。共同语言描述主体、客体、目标、资源、规则、信息、价值、风险和环境；公共机制约束可观察的协作状态；参与者选择自己的策略。

Wishbud 是参考环境，OPC 是参考业务/执行系统，PEA 是经济代理应用，IAP 是可选经济机制。任何一方都不是使用公共契约的先决条件。研究、非营利协作和公共知识贡献不需要伪装成交易。

本次不承诺：自动产生意识/文明、科学因果发现、真实付款、资产流动性、真实 ZK 证明、无限规模、自动信任陌生主体。也不部署生产或调用付费模型。版本是预发布工程基线，不是生产认证。

## 3. 体系边界

| 层 | 职责 | 不承担 |
|---|---|---|
| 语义 | 九要素、归属、版本、引用、证据与声明的区别 | 判定所有人的价值观 |
| 机制 | 提议/接受、权限检查、版本绑定、修订、验收、幂等与恢复 | 选择目标或伙伴、调度模型 |
| 规则集 Profile | 明确媒介类型、复核方式和有限资源边界 | 偷偷扩张已授予的权限 |
| 宿主 | 认证、持久化、私有数据、实际执行、证据来源核实 | 把客户端自报 actor 当作认证 |
| 可选策略/应用 | 规划、匹配、学习、支付、治理、仿真、PEA | 成为公共内核的强制依赖 |

核心包含某种协议，不代表所有参与者必须实现所有角色。观察者、提议者、执行者、复核者和采用者可以分别接入。参与者发布的能力只是声明；授权和实际效果仍需宿主验证。

## 4. 发布与依赖

保留完整 `usmsb-sdk` 和现有 Python 3.14 生产运行基线，避免突然改变已有部署的依赖与 API。

新增独立预发布分发 `usmsb-core`，导入名 `usmsb_core`。它通过已有可移植导出机制从**同一份规范源码**生成，不手工维护第二套核心。默认仅用标准库；已有经验适配器通过 `learning` extra 可选安装 Pydantic。不与 `usmsb_sdk` 争用同一个安装目录。

构建产物包含源码提交、dirty 状态、文件 SHA256 清单和许可证。构建与验收在临时目录完成，不污染主源码和用户 egg-info。分发的制品不能被描述为已发布 PyPI；实际发布另行执行。

完整包的公开导出逐步改为惰性加载：只导入 `Goal` 或协作契约不加载钱包、Web 服务和 LLM provider；访问原有高级类时仍加载原实现，保持名称与含义不变。默认完整安装依赖暂不骤减，后续按真实消费者迁移后再拆分。

## 5. Profile 与兼容性

现有 `goal_contract`、`remote_status`、`world_reference` 默认行为保持兼容，包括旧 schema 和旧 Wishbud 引用。固定 Wishbud 标识格式移到明确的兼容规则集，不作为中立规范的身份制度。

新调用可显式选用中立规则集；新契约携带规则集标识和版本，不默默转换。

- 身份/对象引用包含 authority、namespace、kind、id 和版本（如适用）。引用不是凭证，也不授权自动访问 URL。
- 交付物支持带哈希、媒介类型、大小和位置的引用；内核不下载、不执行外部内容。
- 复核模式明确区分 independent、peer 和 self。自评不得冒充独立复核；默认保守，降低复核要求必须形成新版本并获得相关同意。
- 条数与大小限制是有界配置，有硬上限。开放不等于无限制输入。
- 未支持的必需规则集/版本应拒绝；不理解的附加描述不能自动获得行为权限。

## 6. 最小协作账本

新增标准库实现的 `CollaborationJournal`，作为可嵌入的参考机制，不是中心 World 服务或 Agent 执行器。

命令入口接收宿主已经认证的 `actor`、唯一 `command_id`、操作名和有界 JSON payload。HTTP body 里的身份声明不能代替认证；示例适配器从测试凭据映射 actor。生产宿主需要自己的认证、密钥管理、租户隔离和审计。

每个命令在 SQLite `BEGIN IMMEDIATE` 事务内：检查授权及前置版本、更新投影、追加事件、保存回执。相同命令标识与相同输入重放返回原回执；同标识换 actor/输入/操作必须拒绝。失败不提交部分状态。账本重启后继续保留全部版本与幂等记录。

账本绑定宿主标识及安装的身份/授权配置；更换规则不能通过重启悄悄生效。引用可跨宿主表达，但本次不声称实现了跨 World 复制、共识或全网全序账本。

### 6.1 目标

`goal.create` 由有相应能力的主体创建自己的目标；`goal.revise` 仅由目标所有者提交，必须指定当前基准版本、变更字段和修订依据。身份、所有权不能放进意图补丁。每次产生新版本，不修改旧记录。

目标修订与合同修订分开：所有者可以修订自己的追求，但已有承诺继续绑定原目标版本。回执列出受影响承诺以供重新协商，不自动取消、退款或给他人增加义务。

受影响列表保存为修订时的不可变快照；回执只带前 32 个 ID、总数与下一页游标。宿主通过 `revision_impacts(goal_id, revision, after=..., limit=32)` 读取后续页。后续承诺状态变化不改写这个快照，也不能因为回执膨胀而让高协作数量的目标永远无法修订。分页是宿主读取能力，不是面向公众的无权限查询接口。

### 6.2 协作承诺

`commitment.propose` 明确目标版本、请求者、提供者、交付描述、条款、验收标准、复核者及规则集。提议不构成对方授权。所有必要参与方使用被冻结的提议哈希执行 `commitment.accept` 后才生效。

修订采用新提议引用 `supersedes`，不原地改写。新约定经受影响各方接受后，旧约定才被替代。旧交付、回执和复核历史保留。已完成的合作不得改写成未完成；新目标需要新的合作。

协议本身不托管资金；条款描述也不会预留算力、生成收益或授予数据访问权。实际资源承诺由对应宿主/支付扩展负责。

### 6.3 交付、复核与采用

`artifact.submit` 只接受约定提供方的声明，绑定有效约定和不可变内容摘要。摘要证明字节一致性所需的参照，不证明内容正确；真实文件读取、来源和安全检查由宿主完成。

`review.record` 必须来自约定复核者，绑定确切交付版本，覆盖约定标准，使用 pass/fail/unknown 和证据引用。独立复核检查参与方关系；真实控制主体的独立性需要宿主身份系统证明，不能仅凭不同字符串认定。

`adoption.record` 来自实际采用方，仅允许对已达到约定验收条件的成果记录采用。采用记录仍是可归属的陈述，不自动证明改善或因果关系，不自动完成根目标。

目标已修订时，旧复核对旧约定仍保留意义，但不能作为新目标验收。所有历史查询显示绑定版本，不将旧结果移花接木。

## 7. 执行与不确定状态

外部 Agent 保留自己的运行时、私有记忆、工具和模型。公共内核没有 `exec`、模型自动调用或后台调度。原有异步执行契约保留 accepted/running/completed/failed/unknown 区别。

涉及副作用的调用必须先持久记录操作键，再由宿主执行；断线后的 unknown 状态只允许对原操作进行查询和对账。命令幂等不能提供外部系统“恰好执行一次”的保证；本次不能把 SQLite 幂等包装成全球支付保证。

治理和规则演化可用提议/版本/接受模式表达，但不实现强制全局治理、投票权或自动权力扩张。探索、学习和拒绝合作都是可选策略的合法输出。

## 8. 威胁模型与最低安全约束

| 风险 | 处理 |
|---|---|
| 请求伪造主体 | 认证在宿主；actor 不从业务 payload 读取 |
| 重放或同 ID 换内容 | 身份/操作/输入摘要绑定；持久幂等回执 |
| 越权修订 | 所有者检查、基准版本 CAS、不可变历史 |
| 新目标覆盖旧债务 | 承诺固定目标版本，另行协商 |
| 自我验收冒充独立 | 明确模式；核对宿主提供的控制主体关系 |
| 伪造证据 | 记录声明不等于真实性；宿主验证器核实原始证据 |
| 恶意交付链接 | 内核不自动抓取/执行；宿主单独限制访问 |
| 无限数据/操作 | JSON 有界、配置有上限；身份能力 allowlist |
| 已泄露资料撤销 | 撤销后续授权，不声称收回已披露副本 |
| 学习污染 | 保留既有证据门槛、失效传播、撤销机制 |
| 付款不确定 | 保留 PR #13 fail-closed 行为；不启动新支付轨道 |

本地账本不是操作系统沙箱，不对拥有同一文件系统权限的恶意进程提供隔离；生产需要独立部署、安全凭据及存储保护。

## 9. 兼容与迁移

1. 原有导出路径、默认 schema、Wishbud 标识、策略预算和经济安全行为保持。
2. 新中立 API 和新分发为增量；现有 Wishbud/OPC 无需被本次代码偷偷升级。
3. 新消费者优先安装 `usmsb-core`；已有完整 SDK 消费者可逐个改用新 API。
4. 既有数据不自动重写；升级前备份，恢复旧程序时继续使用旧数据库或已验证的向后兼容版本。
5. 契约 major 不兼容则拒绝；不得把协议版本、包版本、Wishbud 应用版本混成一个数字。
6. 历史文档保留研究价值，但当前入口明确区分“已有代码”“测试覆盖”“真实外部验收”“研究设想”。

## 11. 演进顺序与边界

本轮交付：分支审计、详细设计、中立规则集、可移植分发、参考协作账本、双宿主示例、兼容性及安全回归、当前文档入口整改。

随后在独立议题中推进：生产身份与凭证适配、标准协议互操作认证、真实证据解析器、跨 World 信任选择、真实支付与对账、规模压测、长期有对照的经验演化实验。它们不能由本轮单元测试替代，也不能为了“全部完成”而用模拟回执冒充。

主干合入以实际检查结果为准。设计中出现的验收要求不是已经通过的声明，实际结果统一记录到交付报告。
